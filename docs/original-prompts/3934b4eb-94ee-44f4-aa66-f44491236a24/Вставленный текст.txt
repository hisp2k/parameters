# ИСПОЛНЯЕМЫЙ ПРОМТ ДЛЯ CODEX

Ты работаешь с **существующей SolidWorks-моделью трубного шнекового транспортера**.

Не создавай изделие заново без доказанной необходимости.

Цель: превратить существующую модель в устойчивую параметрическую систему с расчётным Solver, двумя профилями `SHAFTED / SHAFTLESS`, нормативным Rule Engine, MASTER/Skeleton-архитектурой, автоматическим EBOM и выпуском документации.

Работай строго по фазам.

Не переходи к следующей фазе, пока не выполнены критерии `DONE` текущей.

---

# ГЛАВНЫЕ ПРАВИЛА

1. Сначала критическая экспертиза, затем расчёт, затем повторная критическая экспертиза, только после этого CAD.

2. Никогда не использовать `0` вместо неизвестного значения.

Использовать:

`UNKNOWN`

`REQUIRED`

`WARNING`

`BLOCK`

`PASS`.

3. Каждый параметр должен иметь режим:

`FIXED`

`FREE`

`CALCULATED`

`REFERENCE`

`SELECTED`.

4. Не придумывать коэффициенты, ГОСТ, нормативы, типоразмеры или физические характеристики.

5. Все справочные и нормативные значения должны иметь источник и версию.

6. Осевой и безосевой шнеки считать разными механическими профилями.

7. Не считать `SHAFTLESS` как `SHAFTED` с нулевым диаметром вала.

8. Стандартные компоненты подбирать из библиотек.

9. Не выбирать первый вариант, получивший `PASS`.

Формировать несколько допустимых вариантов и сравнивать их.

10. Никакая CAD-деталь не должна управлять MASTER-моделью.

Изменения конструкции проходят:

`Solver → State Point → MASTER → Parts/Assemblies`.

---

# ФАЗА 0 — КРИТИЧЕСКАЯ ЭКСПЕРТИЗА

Проведи критический анализ задачи до изменения модели.

Проверь:

- достаточно ли исходных данных;
- какие параметры действительно известны;
- какие данные противоречат друг другу;
- какие параметры ошибочно приняты константами;
- какие нормативы применимы;
- какие нормативы ещё требуют подтверждения;
- технологические ограничения;
- ограничения по габаритам;
- ограничения существующей модели;
- возможные слабые места архитектуры;
- наличие смешивания SHAFTED/SHAFTLESS;
- наличие фиктивных значений;
- наличие неучтённых нагрузочных режимов.

Сформируй:

`CRITICAL_ANALYSIS_REPORT`.

## DONE PHASE 0

Фаза завершена, если:

- перечислены все критические риски;
- сформирован список `REQUIRED`;
- сформирован список `BLOCK`;
- понятен объём следующего аудита.

# ФАЗА 5 — РАСЧЁТ ПРОИЗВОДИТЕЛЬНОСТИ

Поддерживать ввод:

`Qv`

или:

`Qm`.

Связать их через актуальную насыпную плотность.

Для нескольких горловин рассчитывать:

`Q(x)`.

Не использовать только одно значение расхода для всей длины.

Создать итерационный контур:

`Q`

→ `phi`

→ `D`

→ `P`

→ `n`

→ `Q_ACTUAL`

→ проверки

→ повторный подбор.

`D`, `P`, `n`, `phi` не считать независимыми параметрами.

## DONE PHASE 5

Solver формирует несколько допустимых комбинаций `D/P/n/phi`.

# ФАЗА 6 — ВЕТВЛЕНИЕ SHAFTED / SHAFTLESS

После общей части расчёт обязан расходиться.

## SHAFTED

Рассчитывать:

- наружный диаметр;
- шаг;
- обороты;
- центральную трубу или вал;
- толщину трубы;
- толщину пера;
- длину секций;
- соединения;
- промежуточные опоры;
- подшипники.

Проверять:

- изгиб;
- кручение;
- совместные напряжения;
- прогиб;
- осевую силу;
- усталость;
- сварку;
- соединения.

## SHAFTLESS

Рассчитывать:

- наружный диаметр;
- внутренний диаметр;
- сечение спирали;
- толщину;
- высоту спирали;
- шаг;
- футеровку;
- трение;
- износ;
- хвостовик;
- приводной фланец.

Проверять:

- напряжения;
- крутильную жёсткость;
- деформацию;
- полный момент двигателя;
- усталость;
- износ футеровки.

## DONE PHASE 6

Оба профиля имеют независимые расчётные цепочки и общий интерфейс.

# ФАЗА 8 — ПРИВОД

Подбирать привод только после силового расчёта.

Приоритет:

1. корпоративный типовой мотор-редуктор;
2. стандартный мотор-редуктор;
3. стандартный редуктор + стандартный двигатель;
4. возврат к `D/P/n`;
5. специальный привод только при необходимости.

Проверять:

`T_RUN`

`T_START_FULL`

`T_DRIVE_MAX`

`T_LIMIT`

`T_ALLOW`.

Требование:

`T_RUN < T_START_FULL < T_LIMIT < T_ALLOW_MIN`.

Если мотор-редуктор способен разрушить механику до срабатывания защиты:

`BLOCK`.

## DONE PHASE 8

Выбран конкретный стандартный привод с проверенными рабочим, пусковым и предельным моментами.

# ОБЯЗАТЕЛЬНЫЙ ФОРМАТ ОТЧЁТА CODEX ПОСЛЕ КАЖДОЙ ФАЗЫ

Всегда выдавай:

## PHASE
Номер и название.

## STATUS
`PASS / WARNING / BLOCK`.

## COMPLETED
Что реально сделано.

## FOUND
Что найдено.

## CHANGED
Какие файлы или сущности изменены.

## CALCULATIONS
Какие расчёты выполнены.

## VALIDATION
Какие проверки выполнены и их результат.

## RISKS
Оставшиеся риски.

## REQUIRED
Каких данных не хватает.

## NEXT
Следующая разрешённая фаза.

## COMMIT
Хэш или предлагаемое имя коммита.
