# Структура программы расчёта шнековых транспортёров

**Статус:** проект программной архитектуры для согласования с инженером-расчётчиком. Структура обеспечивает подключение разных сред без смешения неподтверждённых расчётных моделей.

## 1. Контуры системы

```text
ТЗ / измерения / каталоги / производство
              ↓
Input + Provenance + Units
              ↓
Material Classifier → Product Profile → Application Envelope
              ↓
Physical Model + Formula Registry + Coefficient Registry
              ↓
Calculation Core → Candidate Generator → Check Engine
              ↓
Calculation Result + Trace
              ↓
Design Rules + Reference Components → Design State
              ↓
Production Profile → Production State / EBOM / MBOM
              ↓
Утверждённая карта параметров → SolidWorks
```

Расчётное ядро — отдельная библиотека без SolidWorks API и вызовов ИИ. Классификация среды выбирает утверждённую модель; при неоднозначном выборе возвращает запрос данных. У каждого профиля — собственный `physical_model_id`, набор формул, коэффициентов, проверок и границ применимости.

## 2. Модули

| Модуль | Ответственность |
|---|---|
| `input/` | схема ТЗ, AS-IS, ограничений и статусов неизвестности; неизменяемый снимок входа |
| `provenance/` | источник, дата, метод, качество, погрешность и ответственный по каждому значению |
| `units/` | преобразование на границе системы и единая внутренняя SI-система |
| `material/` | каталог сред и состояний, классификатор, проверка полноты свойств |
| `profiles/` | версии Product Profile и матрица применимости формул/проверок |
| `formulas/` | реестр формул и коэффициентов с ID, источником и диапазоном |
| `geometry/`, `capacity/`, `kinematics/` | расчёт кандидата по утверждённой модели |
| `loads/`, `shaft/`, `bearings/`, `drive/`, `housing/` | расчёт обязательных нагрузок и узлов по расчётным случаям |
| `candidates/` | создание конечного набора вариантов из допустимых геометрий и скоростей |
| `checks/` | единый механизм проверок `PASS/WARNING/BLOCK/UNKNOWN/NOT_CHECKED` |
| `selection/` | конструкторские правила и справочники покупных изделий |
| `production/` | доступные материалы и технологии, правила EBOM → MBOM |
| `trace/`, `result/` | полная цепочка выбора, версии и стабильные схемы результатов |
| `cad_adapter/` | только утверждённая карта `Design State → SolidWorks` |

## 3. Обязательные структуры данных

```text
MeasuredValue<T> = {
  value, unit, min, max, uncertainty, source_id, measured_at,
  method, confidence, confirmed_by, status
}

MaterialProfile = {
  id, version, state_class, properties{}, valid_ranges{},
  physical_model_id, formula_set_version, coefficient_set_version,
  required_properties[], evidence_refs[]
}

LoadCase = {id, duration, assumptions[], input_overrides{}, required_checks[]}

CheckResult = {
  id, candidate_id, load_case_id, status, actual, limit, unit,
  utilization, formula_id, source_refs[], message
}

CalculationResult = {
  input_snapshot_id, model_version, material_profile_version,
  normative_profile_version, component_catalog_version,
  candidates[], checks[], unknowns[], warnings[], blocks[], trace[]
}

DesignState = {calculation_result_id, selected_candidate_id,
  selected_standard_parts[], design_rule_ids[], reasons[]}

ProductionState = {design_state_id, production_profile_version,
  substitutions[], EBOM, MBOM, process_routes[]}
```

Каждое поле имеет строгий тип и единицу. Идентификаторы и версии сохраняются с изделием, чтобы старый расчёт воспроизводился после обновления программы. Текстовое значение `UNKNOWN` не заменяется числом без события в `trace`.

## 4. Порядок выполнения расчёта

1. Принять исходный снимок и проверить размерности, диапазоны, обязательные поля и противоречия.
2. Определить класс физического состояния и выбрать ровно один утверждённый `Product Profile`; иначе вернуть `UNKNOWN` или `BLOCK`.
3. Проверить вход и запрошенный режим по `Application Envelope` профиля.
4. Построить `min/nominal/max` сценарии для неопределённых критических свойств и заданные `LoadCase`.
5. Сформировать геометрические и кинематические кандидаты из разрешённых рядов без скрытой оптимизации.
6. Для каждого кандидата запустить расчёт подачи, нагрузок, вала, опор, привода и корпуса по применимым формулам.
7. Применить проверки по всем обязательным случаям; блокирующий случай отклоняет кандидата.
8. Вернуть кандидатов с причинами `PASS/WARNING/BLOCK/UNKNOWN`, промежуточными значениями и трассировкой.
9. После инженерного принятия применить `Design Rules` и каталоги; затем учесть производственные ограничения отдельно.
10. Передать в CAD только утверждённый `Design State` после соответствующего Release Gate.

Если для профиля нет утверждённой формулы мощности или пуска, кандидаты могут быть показаны как предварительные, но итоговый статус не может быть `PASS` и выпуск запрещён.

## 5. Правила изменения и проверки

Изменение формулы, коэффициента, диапазона применимости или стандартного ряда создаёт новую версию. CI выполняет тесты единиц, размерностей, синтетических сочетаний, границ, отказов и регрессии. Golden Dataset содержит вход, ожидаемый результат, допуск, источник и версию модели. Отдельный независимый референсный расчёт проверяет ключевые промежуточные величины; он не использует функции production-core. Исторические изделия служат инженерной валидации с учётом качества данных, а не автоматической «истиной».

## 6. Порядок реализации

| Этап | Проверяемый результат |
|---|---|
| 1. Данные и профили | схемы входов, `MeasuredValue`, статусы, единицы, выбор среды и область применимости |
| 2. Инженерное основание | FBD, паспорта первого материала, Formula Registry, Coefficient Registry, референсный расчёт |
| 3. Ядро MVP | независимый расчёт первого горизонтального трубного профиля, кандидаты, проверки, trace |
| 4. Валидация | чувствительность, исторические случаи, Golden Dataset, границы и тесты |
| 5. Конструкция | Design Rules, каталоги компонентов и стабильный `Design State` |
| 6. CAD и производство | карта параметров, SolidWorks, EBOM → MBOM после Release Gates |
| 7. Новые среды | новый паспорт физической модели и коэффициентов; повторная валидация до разрешения `PASS` |

## 7. Решения, которые ещё нужны

1. Выбрать конкретный первый сыпучий материал и получить его измеренный паспорт.
2. Утвердить методику для производительности и сопротивления перемещению в первом профиле.
3. Утвердить FBD, расчётные режимы и пределы для вала, опор, привода и корпуса.
4. Определить стандартные ряды, каталог компонентов и производственный профиль.
5. Собрать исходные и эксплуатационные данные исторических изделий.

Эти решения являются входом для инженерной валидации; структура программы может разрабатываться до них, но расчётные формулы не следует объявлять выпущенными.
