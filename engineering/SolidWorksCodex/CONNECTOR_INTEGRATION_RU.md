## Что реализовано

- Python отправляет каждый запрос отдельным файлом и читает ответ только по
  уникальному request_id. Проверяются идентичность инструмента, булевый статус,
  успешность вложенного worker-ответа и код завершения PowerShell.
- PowerShell принимает `-RequestFile`; старый request.json оставлен для совместимости.
  Каталоги создаются безопасно при одновременном первом запуске.
- Импортирована защита владельца блокировки и карантин после таймаута.
  Убрано автоматическое удаление блокировки по PID/возрасту: дочерний worker
  может ещё работать. Проверка карантина и его сброс выполняются под блокировкой.
- stdout/stderr читаются отдельными асинхронными .NET задачами.
  Неразбираемый результат потенциальной записи также устанавливает карантин.
- Таймаут worker задаётся запросом, внешний таймаут Python имеет запас 30 секунд.
  Неопределённый исход никогда автоматически не повторяется.
- CAD-адаптер разбирает фактические вложенные ответы C# и массив items.
  Неполное чтение, неизвестные значения и неоднозначные имена отклоняются.
- Перед изменением проверяются все входные параметры, единицы и разрешённый
  класс операции. Нужен явный абсолютный source_path, совпадающий с активной
  чистой деталью. Запись поддерживает только управляемые линейные AI_* размеры.
- Одна команда sw_create_parameter_variant выполняет создание копии, перенос
  имён размеров, перестроение и сохранение. Адаптер проверяет неизменность
  исходника, фактические размеры и подтверждение сохранения без предупреждений.
- parameter_update_verified сообщает только об этом ограниченном результате.
  ok остаётся false, пока не обеспечены повторное открытие с диска, проверки
  пересечений/зазоров и инженерная приёмка. Неизвестные проверки перечисляются
  в unknown_checks. Масса и другие не прочитанные величины остаются None.
- Web-тесты используют изолированный fake-транспорт даже на Windows.

## Проверка

Из корня репозитория с зависимостями calculator/requirements.txt:

```powershell
python -m pytest calculator/tests -q
powershell -NoProfile -ExecutionPolicy Bypass -File RUN_CLAUDE_BRIDGE_TESTS.ps1
.\SolidWorksLocal.exe --self-test
powershell -NoProfile -ExecutionPolicy Bypass -File TEST_ASSEMBLY_READ_REGRESSIONS.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File TEST_WRITE_SAFETY_REGRESSIONS.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File TEST_SCOPED_EXPERIMENT.ps1
```

Тесты test_bridge_transport.py запускают реальные PowerShell-процессы с
скомпилированным FakeWorker в pytest tmp_path. CAD не вызывается. На других
ОС эти процессные тесты пропускаются; остальные остаются автономными.
RUN_CLAUDE_BRIDGE_TESTS.ps1 также использует только FakeWorker и теперь
возвращает ненулевой код при неуспешной проверке.

Результаты проверок этой интеграции: см. заключительную запись ниже.

## Ограничения и следующий этап

Живой параметрический сценарий этой версией адаптера не выполнен. Исходный
EXE не пересобран и установленный MCP не заменён. При первом полном прогоне
унаследованные web-тесты сделали три sw_status на локальном коннекторе;
после этого тесты изолированы от рабочего CAD. Запись CAD не запускалась.

Это транспорт отдельного вызова, а не долговечная очередь заданий. Идентификаторы
создаёт клиент заново; архив запросов/ответов служит диагностике. Повторное ручное
выполнение старого request.json может повторить операцию: идемпотентность задания
и восстановление многошагового сценария требуют следующего слоя оркестрации.
Старые клиенты с общим request.json нельзя запускать одновременно.

Пакетная BOM, генератор ЕСКД, DXF и новая методика расчёта этим изменением
не реализуются. Следующий проверяемый результат — управляемый живой пилот
на явно выбранной копии с настоящим закрытием/reopen и измерениями, затем
долговечные задания и пакетное чтение.
