## Актуально: Новый Инструмент sw_set_global_variable (Именованные Переменные)

По прямому указанию пользователя («продолжай дорабатывать задания Дмитрия Александровича»,
после свода вопросов ниже) начата реализация САМОЙ явной прямой формулировки Дмитрия
Александровича из стратегического брифинга: «нам нужно подменить числовые значения на
параметрические значения... не будет 2 стоять, а будет переменная». Это не эксперимент на
конкретном заказе, а системное расширение коннектора, работающее независимо от блока A
свода вопросов (не требует опросного листа/матмодели/BOM-версии/техно-калькулятора —
это инфраструктура, которая понадобится, когда те данные придут).

Добавлен новый write-инструмент `sw_set_global_variable` (`src/Protocol.cs`,
`src/SolidWorksReader.cs`): берёт тот же явно выбранный элемент/размер, что и уже
проверенный `sw_set_feature_dimensions` (`feature_name`/`expected_feature_type` из
`sw_features`, точный `full_name`/`expected_current_mm`), но вместо прямой записи числа
через `IDimension.SetSystemValue3` добавляет через `IEquationMgr.Add3` два уравнения:
именованную глобальную переменную (`"variable_name" = value_mm`, новое имя) и уравнение
самого размера, ссылающееся на неё (`"D1@Элемент@Файл" = "variable_name"`). Значение может
совпадать с текущим — смысл не обязательно менять число, а сделать его именованной
переменной, как прямо сказал Дмитрий Александрович. Уже управляемый уравнением размер и
уже занятое имя переменной — отклоняются явно (не перезаписываются молча). После
перестроения обе добавленные записи и итоговое значение размера перечитываются заново из
`IEquationMgr`/`IDimension` как отдельная проверка. При любом сбое после добавления обе
записи удаляются и размеру возвращается прежнее буквальное значение перед повторным
перестроением (тот же принцип отката, что и у `sw_set_feature_dimensions`). Подробности
и обоснование выбора API — см. новый раздел README_RU.md «Именованные Параметрические
Переменные (sw_set_global_variable)».

## Исправления после ревью директорского пилота

- `sw_component_details`: масса, объём и площадь возвращаются только при
  совпадении активной конфигурации документа с конфигурацией экземпляра до и
  после чтения. Иначе `mass_properties=null`, статус `UNKNOWN`, причина в
  `issues`; переключения конфигураций нет.
- `sw_component_details` и `sw_assembly_tree`: `IsVirtual` читается как свойство.
- `sw_equations`: область действия читается методом `GetConfigurationOption`.
  Имена конфигураций остаются явно `UNKNOWN`: соответствующего getter в API нет.
- Проверка корня сборки сопоставляет полные нормализованные пути из пар
  имя/путь API. Одноимённые файлы из других каталогов не создают ложных связей.
  Неполные ответы отклоняются; сценарий использует собственный каталог и
  возвращает ненулевой exit code при FAIL.
- **`OpenDoc6` (открытие read-only, `sw_open_assembly_readonly`)**: разделены
  два разных исхода. Если `OpenDoc6` не вернул документ — это настоящий
  `OPEN_FAILED`. Если документ реально открылся, но SOLIDWORKS сообщил
  `errors != 0`, результат доступен только при подтвержденном read-only:
  `OPENED_WITH_LOAD_ERRORS`, сырые `errors`/`warnings` сохранены. Обычное
  открытие детали с ошибками останавливается с `OPEN_LOAD_ERRORS`.
  При `errors=0`, `warnings!=0` чтение возвращает `OPENED_WITH_WARNINGS`;
  `OPENED_CLEAN` означает строго оба нулевых кода.
- Создание варианта требует чистой загрузки как исходника, так и копии:
  ошибки и предупреждения блокируют продолжение до изменения параметров.
  Проверяется фактический тип через `IModelDoc2.GetType`; read-only операция
  завершается ошибкой, если `IsOpenedReadOnly` вернул false или недоступен.
- Проверено: сборка .NET Framework x64 и 258 offline-проверок; portable-сборка
