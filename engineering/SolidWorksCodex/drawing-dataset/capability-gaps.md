# Анализ возможностей коннектора по комплекту production drawing dataset

Источник: `комплект_подготовки_производства_P1.zip` (436 PDF, 257 уникальных по содержимому — 179 файлов дублируются между несколькими путями в архиве, в основном между старой и текущей копией папки проекта «Шнековый транспортер»).

Этот проход — текстовый (pdftotext + pdfinfo), без визуального постраничного анализа. У всех 436 файлов есть текстовый слой, поэтому OCR не потребовался. Обозначение и наименование взяты из имени файла (соглашение цеха «<обозначение>  <наименование>.pdf») — это использование имени файла только для идентификации документа, не как доказательство геометрии, как и требуют правила. Материал/масштаб/масса взяты из текста титульного блока только там, где явно найдено совпадение. Геометрические размеры везде оставлены `UNKNOWN` — их невозможно надёжно восстановить только из текста: числа на чертеже это подписи выносных линий, привязанные к 2D-положению на листе, а не к своей детали в тексте; текстовый экстрактор их линеаризует без этой привязки. Понадобится визуальный постраничный просмотр — см. `progress.json`.

## Разбор по типу документа

- Чертежи-кандидаты в отдельную деталь: **130**
- Сборочные чертежи (_SB/СБ): **277**
- Спецификации (_SP/специф.): **21**
- Служебные документы (листы согласования, отчёты, руководства): **8**

Архив в основном состоит из **готовых сборок** (затвор 877/878, шнековый транспортер, решётка шнековая) — сотни сборочных чертежей, спецификаций и деталей внутри сварных узлов. Коннектор принципиально строит одну параметрическую деталь за раз и не собирает сварные узлы или сборки — это архитектурное ограничение, а не пробел, который стоит закрывать построением геометрии.

### Листовой гиб (sheet-metal): линии гиба, радиус, развёртка/плоский шаблон

## Решение

Реализуется: **протяжка постоянного сечения профиля (уголок / круглая труба / прямоугольная труба) на заданную длину с перпендикулярными торцевыми резами и отверстиями на выбранных гранях** (новый MCP-инструмент `sw_create_profile_part_from_plan`, новый класс `src/ProfilePartPlan.cs`).

Обоснование: это единственная универсальная возможность, независимо подтверждённая как в этом архиве (1 явный «Уголок» с полными размерами, AISI 304, масштаб 1:5, 28 отверстий по факту линейного массива), так и в предыдущем анализе `DRAWING_DATASET_ANALYSIS_RU.md` (3 детали: уголки и труба). Гнутый лист покрыл бы больше чертежей (39 в этом архиве), но: (а) реализация требует нового класса COM-вызовов sheet-metal, которые в коде никогда не использовались — риск выше; (б) большинство просмотренных чертежей гиба ссылаются на отдельный DXF-файл развёртки («Предоставить развертку в формате DXF»), которого нет в архиве, — большая часть всё равно получит статус `BLOCKED` даже после реализации. Это отдельная будущая ветка, а не приоритет сейчас.
