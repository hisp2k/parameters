# Программа ввода данных шнекового транспортёра

Настольная программа на Python 3 с графическим интерфейсом Tkinter. Для ввода данных внешние библиотеки не нужны. Для передачи параметра в CAD требуются SolidWorks и `pywin32` на Windows.

## Запуск

В Windows дважды щёлкните `Запустить.bat` либо выполните в этой папке:

```powershell
python app.py
```

Сначала укажите количество загрузочных горловин (1–7) и точек выгрузки (1–2). Программа покажет поля для каждой точки. Можно сохранить незаполненный **черновик** или проверить все обязательные поля и сохранить JSON со статусом `validated_questionnaire`.

Опоры корпуса рассчитываются по рабочей длине желоба с максимальным шагом **3000 мм**: число позиций каждого из двух исполнений (`25.SHT.G.01.01.00.00` и `25.SHT.G.08.00.00.00`) равно `ceil(длина/3000)+1`. При длине 2885 мм программа выдаёт по две опоры каждого исполнения, при 3001 мм — по три. Количество пересчитывается при изменении длины и сохраняется в проверенном JSON в `inputs.body_support_layout`. Фактические координаты опор и крепёж ещё требуют связи с CAD-сборкой; программа пока считает количество опорных узлов.

Открыть ранее сохранённый JSON можно кнопкой **Открыть JSON**. При проверке программа сверяет числовые диапазоны, положение отверстий внутри рабочей длины, допустимые пары диаметра и шага из таблицы [ГОСТ 2037-82](https://files.stroyinf.ru/Data2/1/4294751/4294751811.pdf), а также сумму расходов при одновременной работе точек.

Проверить сохранённый файл без открытия окна:

```powershell
python app.py --check "путь\к\данные_транспортера.json"
```

## Связь с моделью SolidWorks

Поместите папки `transport_questionnaire` и `25.SHT.G_parameterized` рядом. В форме заполните и проверьте данные, затем нажмите **Связать с моделью** и выберите папку `25.SHT.G_parameterized`. Для нынешней сборки нужно вручную указать диаметр **200 мм** и числовой шаг. Программа передаёт шаг в параметр `SCREW_PITCH` детали шнека, перестраивает деталь, считывает фактический размер, сохраняет её и создаёт в папке модели файл `СВЯЗЬ_С_ОПРОСНЫМ_ЛИСТОМ.json` со всеми исходными данными и перечнем ещё не связанных размеров.

Можно выполнить то же действие из командной строки:

```powershell
python cad_bridge.py "путь\к\данные_транспортера.json" --dry-run
python cad_bridge.py "путь\к\данные_транспортера.json"
```

Если модель лежит отдельно, добавьте `--model "путь\к\25.SHT.G_parameterized"`. Режим `--dry-run` только проверяет совместимость и ничего не меняет. При неподдерживаемом диаметре или неопределённом шаге изменение CAD блокируется.

**Геометрически связан только шаг шнека D=200 мм.** Длина желоба, наклон, диаметр, загрузочные и разгрузочные патрубки, опоры и привод в сборке пока не меняются. Их значения сохраняются в отчёте для дальнейшей параметризации. После передачи шага сборку следует открыть в SolidWorks и перестроить; совместимость всех компонентов не проверена автоматически.

Анкета сама по себе не рассчитывает мощность или производительность. Статус `validated_questionnaire` означает только, что поля заполнены и прошли встроенные проверки; для предварительного расчёта прочности используйте отдельную вкладку ниже. Во вкладке материала есть справочная карточка для мелкой свинцовой руды; другие материалы пока вводятся вручную до расширения каталога.

Карточка `KWS_LEAD_ORE_FINE` содержит верхнюю насыпную плотность 4325 кг/м³ из диапазона 200–270 lb/ft³ [таблицы KWS](https://www.kwsmfg.com/engineering-guides/screw-conveyor/bulk-material-table/) и расчётную крупность 3,2 мм, подтверждённую пользователем. Абразивность, сыпучесть и температура этой партии ещё не заданы. Плотность свинцовой руды превышает область применения ГОСТ 2037-82, поэтому проверка анкеты выдаёт предупреждение о нестандартном исполнении. Справочная плотность подлежит проверке для фактического материала.

Для исходной проверки пользователь указал влажность 80 % по массе влажной смеси. Программа отмечает справочную плотность статусом `requires_wet_material_confirmation`; в предварительном отчёте Simulation масса партии и массовый расход оставляются пустыми до подтверждения плотности влажной смеси.

## Предварительный расчёт в SolidWorks Simulation

Во вкладке **6. Прочность** задайте расчётный крутящий момент, осевую силу, точное имя материала из установленной библиотеки SolidWorks, расчётный предел текучести и требуемый коэффициент запаса. Момент и силу следует выбирать для худшего режима работы, включая пуск и возможную закупорку. Расчётный предел текучести может быть консервативно ниже библиотечного, но программа отклонит значение выше библиотечного. Размер элемента сетки можно оставить пустым.

После нажатия **Рассчитать в SolidWorks Simulation** программа:

1. Проверяет заполненную анкету и совместимость с копией модели D=200 мм.
2. Рассчитывает справочные массу партии (`ρ·V`), её вес (`ρ·V·g`) и массовый расход (`ρ·Q`). Эти величины **не прикладываются к валу автоматически**: масса груза действует и на желоб, и на шнек, а распределение зависит от заполнения и контактов.
3. Создаёт линейное статическое исследование для детали `25.SHT.G.02.00.00.03  Вал.SLDPRT`: торец `z=0` жёстко закреплён, на торец `z=−363 мм` приложены заданные сила по нормали и крутящий момент вокруг оси. Назначает выбранный материал, строит сетку и запускает решатель.
4. Считывает максимальные напряжение Мизеса и перемещение; вычисляет коэффициент `расчётный предел текучести / максимальное напряжение Мизеса`. Сохраняет исследование и пользовательские свойства `FEA_*` в детали вала, переносит шаг шнека в связанную деталь и записывает `РАСЧЁТ_ПРОЧНОСТИ_ВАЛА.json` в папке модели.

Без изменения CAD можно проверить исходные данные в командной строке:

```powershell
python strength.py "путь\к\данные_транспортера.json" --dry-run
python strength.py "путь\к\данные_транспортера.json"
```

Для запуска из CLI JSON должен содержать раздел `inputs.strength` с полями `torque_nm`, `axial_force_n`, `simulation_material`, `yield_strength_mpa`, `required_safety_factor`; `mesh_size_mm` можно оставить пустым. При отдельном расположении модели добавьте `--model "путь\к\25.SHT.G_parameterized"`.

**Результат относится только к указанному валу и принятой схеме закрепления.** Шнек в сборе, желоб, опоры, сварные швы, подшипники, динамика, усталость и сходимость сетки не проверяются. Это предварительная проверка компонента, а не итоговый расчёт прочности транспортёра. Значения расхода и объёма из анкеты сами по себе не определяют момент и осевое сопротивление; поэтому эти нагрузки вводятся отдельно. Для итогового расчёта потребуется согласовать расчётные случаи и реальные закрепления.

Использованные операции API соответствуют официальным примерам [создания исследования и запуска решателя](https://help.solidworks.com/2026/english/api/swsimulationapi/Add_Remote_Load_Example_VB.htm) и [назначения закреплений](https://help.solidworks.com/2024/english/api/swsimulationapi/SolidWorks.Interop.cosworks~SolidWorks.Interop.cosworks.ICWLoadsAndRestraintsManager~AddRestraint.html).

## Покупные изделия и раздел спецификации

Во вкладке **7. Покупные изделия** загружены 27 позиций (41–44 и 63–85) из переданной спецификации сборки `25.SHT.G.00.00.00.00 СБ.csv`. Позиции 41–44 относятся к узлу крышки и также являются покупными. У каждой строки можно изменить обозначение, количество, группу и примечание; отметка **Включить в спецификацию** управляет выгрузкой. После изменения нажмите **Применить к строке**. Можно добавить своё изделие или удалить созданную строку. Строки исходной спецификации остаются раздельными, в том числе повторяющиеся позиции крепежа, поскольку они могут относиться к разным узлам.

Кнопка **Выгрузить раздел спецификации CSV** создаёт таблицу с выбранными позициями в кодировке UTF-8 BOM и разделителем `;`. Выбор сохраняется вместе с анкетой в `inputs.purchased_items` и восстанавливается при открытии JSON. Исходный каталог встроен в `purchased_catalog.json`, поэтому после копирования программы исходная папка на рабочем столе не нужна.

Штатная CAD-сборка содержит **4 подшипника NSK 7213BEA** (посадка вала Ø65 мм, наружная посадка обоймы Ø120 мм). Если в перечне выбран другой подшипник или иное количество, проверка анкеты выводит предупреждение о необходимости расчёта опор и проверки сопряжённых деталей. Редактирование строки спецификации само по себе не заменяет подшипник в CAD и не подтверждает прочность или ресурс. Данные каталога и количества отражают исходную сборку и подлежат проверке для нового типоразмера транспортёра.

## Расчётный паспорт нагрузок

`load_cases.py` формирует отдельный паспорт нормального режима, пуска, закупорки (если предусмотрена) и реверса (если предусмотрен). Момент двигателя вычисляется из заданных мощности и выходной частоты вращения по `T = 60 000 P/(2πn)` в Н·м. Осевые и радиальные силы, предел момента защиты, схема опирания и источники величин задаются отдельно. Команда `--check` проверяет данные без записи:

```powershell
python load_cases.py "путь\к\данные_транспортера.json" --model "путь\к\25.SHT.G_parameterized" --check
```

Паспорт пока не запускает Simulation и не перестраивает вал или обоймы. Для автоматического выбора другого типоразмера подшипника нужны расчётные реакции обеих опор, осевая схема пары и преднатяг, проверка ресурса и статики, размеры заплечиков, стопорных колец, манжет и сопряжений в сборке. Статический расчёт одного вала с жёстким закреплением не даёт этих данных.
